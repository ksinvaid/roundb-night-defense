# 기획 구상: 땅따먹기 io (가칭)

작성: 2026-10-31, 사용자 구술을 정리한 초안. 확정된 것이 아니라 **다음 세션이 사용자와 함께 다듬는 출발점**이다.
참고한 원작 "로드io"는 정리한 쪽이 직접 확인하지 못했고, 사용자 기억에 의존한다. 원작 규칙을 단정하지 말 것.

## 한 줄 요약

큰 맵을 돌아다니며 돈을 모으고, 타워를 짓고, 유닛을 뽑아 땅을 넓히며 순위를 겨루는 무한 경쟁 게임. 맵 한가운데 보스(용)를 잡으면 큰 보상이 있다.

## 사용자가 말한 재미 요소 (원문 요지)

1. 큰 맵을 자유롭게 돌아다닌다.
2. 돈(자원)을 먹는다.
3. 타워를 짓는다.
4. 유닛을 뽑는다.
5. 땅따먹기: 내 영역이 곧 점수와 수입.
6. 순위 경쟁.
7. 가운데 용(보스)을 잡는 목표.
8. 끝이 없는 무한 경쟁.

## 이 저장소의 게임과 겹치는 부분

이미 있는 것(README 기준)을 재사용하면 처음부터 만들 필요가 없다.

| 구상 | 이미 있는 것 | 비고 |
|---|---|---|
| 돌아다니기 | 다 같이 모드의 아바타 이동(WASD·클릭) | 지금은 한 층 크기. 맵을 키워야 함 |
| 건설 | 건설(B·숫자 1~6), 칸 수 한도 | 영역 개념과 연결해야 함 |
| 유닛 | 인턴·대리·팀장(7·8·9), 집결 지점 | 그대로 쓸 수 있음 |
| 보스 | 보스가 오는 길 표시 | "가운데 고정 보스"로 바꿔야 함 |
| 순위 | 점수 공식, 랭킹 탭 | 영역 점수를 공식에 추가 |
| 사람과 함께 | PeerJS 기반 P2P, 방장 계산 | 인원 한계 있음(아래) |
| AI 동료 | 모자란 자리를 AI가 채움 | 봇 채우기로 확장 가능 |

## 새로 필요한 것

- **영역 시스템**: 타워와 유닛이 땅을 점유하고, 영역이 넓을수록 수입이 늘어난다. 영역 경계에서 충돌.
- **큰 맵**: 카메라 이동, 보이는 범위만 그리기(성능).
- **중앙 보스 이벤트**: 주기적으로 나타나거나 항상 있고, 처치한 팀이 보너스를 받는다.
- **무한 진행**: 판이 끝나지 않고 점수로 순위가 갈린다. 죽으면 재시작 또는 부활.
- **자원 배치**: 맵 곳곳에 돈이 생성된다.

## 단계별 제안

1. **P0 싱글 + 봇**: 서버 없이 한 브라우저에서. 봇 여러 명과 영역 싸움. 재미가 있는지 여기서 판단한다.
2. **P1 점수 저장**: 영역·처치 점수를 기존 랭킹에 올린다.
3. **P2 소규모 P2P**: 기존 방장 계산 방식 그대로. 인원은 적게(예: 4~6). 방장이 나가면 끝나는 한계도 그대로.
4. **P3 서버형(보류)**: 많은 인원이 필요해질 때만. 서버 비용·부정행위 대응이 따로 든다. 지금은 하지 않는다.

## 추가 기능: 문의·게임평 게시판

사용자 요청(2026-10-31). 아직 구현하지 않았고, 요구사항만 기록한다.

### 요구사항

- 게시판 형식. **누구나** 글을 쓸 수 있다(로그인 없이 가능한지는 열린 질문).
- 말머리는 최소 **문의**와 **게임평** 두 가지.
- 모든 글의 **기록이 전체 목록으로 남는다.** 누구나 목록을 볼 수 있다.
- 글쓴이가 **공개 / 비공개**를 고른다.
  - 공개: 제목과 내용이 모두 보인다.
  - 비공개: 목록에는 **제목만** 보이고 내용은 숨겨진다.

### 구현할 때 꼭 지킬 것

- 이 게임은 GitHub Pages 정적 사이트라 **서버가 없다.** 게시판은 별도 저장소(예: Firebase, Supabase 같은 무료 백엔드)가 필요하다.
- **비공개 내용은 서버에서 막아야 한다.** 화면에서만 숨기고 데이터는 브라우저로 내려보내면 누구나 개발자 도구로 볼 수 있다. 읽기 규칙(보안 규칙)에서 비공개 글의 내용 필드를 일반 사용자에게 주지 않도록 하거나, 제목 목록과 내용을 서로 다른 곳에 저장한다.
- 글쓴이가 자기 비공개 글을 다시 보려면 본인 확인 수단이 필요하다(글 작성 시 확인용 비밀번호 또는 로그인). 운영자는 비공개 글을 볼 수 있어야 문의에 답할 수 있다.
- **스팸·도배·욕설 대응**: 글 쓰는 간격 제한, 길이 제한, 운영자 삭제/숨김 기능.
- 글쓴이에게 **개인정보(전화번호·주소 등)를 내용에 쓰지 말라는 안내**를 글쓰기 화면에 표시한다. 비공개여도 마찬가지다.
- 키·비밀번호는 코드에 쓰지 않는다. 공개 저장소이므로, 백엔드의 공개용 키가 필요하면 그 키가 공개되어도 안전하도록 보안 규칙부터 설정한다.
- 이 저장소는 공개이므로 게시판 글을 저장소 파일로 저장하지 않는다.
