# 라운드비 나이츠 작업 룰북

이 저장소(`ksinvaid/roundb-night-defense`, 브랜치 `main`)는 **사용자가 일을 시키는 3곳이 함께 쓴다**(Codex, 데스크톱 Claude 로컬 세션 "검색자 클론", 그 외 1곳). 어느 곳이든 나이츠 작업을 하기 전에 이 문서를 읽고 따른다. 기준이 틀리면 사용자에게 먼저 묻는다.

## 1. 가장 중요한 규칙
- **나이츠 작업은 매번 이 저장소에 커밋하고 푸시한다.** 내 PC나 대화에만 두지 않는다. 사용자가 따로 말하지 않아도 한다.
- 푸시하면 실제 게임에 바로 반영된다(GitHub Pages). 올리기 전에 아래 4번 검증을 한다.
- 3곳이 같은 파일(`index.html`)을 동시에 고치므로, **남의 변경을 지우지 않는다.**

## 2. 작업 시작 전
1. `git pull --rebase origin main` 으로 최신을 받는다.
2. `git log -10 --format='%h %an %s'` 로 다른 곳이 방금 고친 부분을 본다. 같은 부분을 고칠 거면 그 내용을 먼저 읽는다.
3. 고칠 범위를 작게 잡는다. 한 번에 하나의 주제만 한다.

## 3. 커밋·푸시
- **주제 하나당 커밋 하나.** 첫 줄은 영어 한 줄(Codex 커밋 형식과 맞춘다). 본문에 원인, 바꾼 것, 확인한 것, **확인 못 한 것**을 적는다.
- 작성자 이름은 쓰는 곳을 알아볼 수 있게 둔다(`git config user.name`): `Codex` / `검색자 클론 (Claude)` / 세 번째 곳의 이름.
- 푸시 직전에 `git fetch origin main` 후 `git pull --rebase origin main`.
- 충돌이 나면 **양쪽 내용을 모두 살려서** 합친다. 합치기 어렵거나 의도를 모르겠으면 멈추고 사용자에게 묻는다.
- **금지:** `git push --force`, 남의 커밋 되돌리기(`revert`/`reset`)는 사용자가 지시했을 때만. 큰 파일(영상 등) 커밋 금지.

## 4. 올리기 전 검증 (최소 기준)
1. **문법 검사:** 메인 `<script>`(약 4201행~`</script>`)를 뽑아서 Node로 컴파일한다.
   `new vm.Script(fs.readFileSync("main.js","utf8"))` 가 오류 없이 끝나야 한다.
2. **바꾼 로직 단독 시험:** 가능한 부분은 따로 떼서 돌려 본다. 던전 맵은 `dgnMap` 묶음(`const dgnMap = (() => {` ~ `})();`)을 꺼내 `dgnMap.gen(n)` 으로 98~150층을 만들어 본다.
3. **실제 화면:** 가능하면 직접 열어서 확인한다. 못 했으면 커밋 본문과 사용자 보고에 "화면 확인 못 함"이라고 적는다.
4. 올린 뒤 사이트 반영은 5~10분 걸린다(캐시 10분). 확인은 `curl` 로 바꾼 줄이 사이트에 있는지 본다.

## 5. 공개 저장소 규칙
이 저장소는 **공개**다. 다음은 절대 올리지 않는다.
- 비밀번호, API 키, 토큰, 인증 파일, `.env`
- 개인 식별정보(실명 연락처, 주소, 전화번호), 계좌·카드 정보
- 영상·큰 이미지. 서버(Code.gs 등)의 비밀 설정

## 6. 구조 메모 (던전, 함정 방지)
- **던전은 150층까지**다. 층 번호로 `d = floor((n-1)/10)` 을 구하고, 100층과 101~150층은 `spec()` 의 마지막 `default:` 분기(대표실 단계)를 함께 쓴다. 이 분기를 바꾸면 101층 이후 난이도가 같이 바뀐다.
- **`LOOK`(층 배경 스타일)은 10칸**이다. 맵 생성은 `look: sp.d % 10` 으로 순환한다. 새 `LOOK[...]` 인덱스를 쓸 때는 항상 `% LOOK.length` 와 `|| LOOK[0]` 안전장치를 둔다. (2026-11-07: 101층에서 `reading 'fb'` 오류의 원인)
- **125층 이후 추가 난이도**는 `DEEP` 객체(`DCFG` 바로 위)에 모아 뒀다. 시작 층, 몹·보스 체력/공격 배율, 층당 증가폭, 몹 밀도를 한 줄에서 조절한다. 111층부터의 기본 배율(몹 체력 ×1.45, 공격 ×1.55)은 `spawnMob` 에 따로 있다.
- 파티 인원 보정(`setPartyMul`): 몹 마릿수 +50%/명, 체력 +40%/명, 공격 +5%/명. 난이도는 3인 파티를 기준으로 본다.
- **던전 단축키:** WASD 이동, 1~8 스킬, E 사용, Q 물약, I·K·C 메뉴, M 지도, Tab 층 선택, J 공격, **R 밧줄로 따라가기**(보스방에 먼저 간 파티원이 있을 때만). 새 키를 넣을 때는 이 목록과 겹치지 않게 한다.
- `index.html` 안 `/* ===ENGINE_START=== */ ~ ENGINE_END` 처럼 화면과 분리된 순수 엔진 부분은 노드에서 시험할 수 있게 유지한다.

## 7. 원본 소스에서 다시 빌드할 때
예전에는 회사 PC의 `라운드비_디펜스게임\` 소스에서 빌드해 올렸다. 지금은 이 저장소의 `index.html` 을 직접 고친다. 옛 원본에서 빌드한 파일을 올리면 최근 고침이 사라질 수 있으니, **올리기 전에 반드시 `git pull` 하고 `git diff` 로 최근 커밋의 변경이 남아 있는지** 확인한다.

## 8. 사용자 보고
작업을 끝내면 사용자에게 이렇게 알린다.
- 올린 커밋 해시와 한 줄 요약
- 확인한 것 / **확인 못 한 것**(특히 실제 화면, 전투 체감)
- 사이트 반영에 걸리는 시간과 새로고침 방법
